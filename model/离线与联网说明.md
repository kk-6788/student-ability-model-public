# 离线与联网说明

## 运行

在已安装 Node.js 的 Windows 电脑上双击 `启动系统.cmd`，保持窗口运行，并打开 <http://localhost:8765/>。也可在本目录执行 `node server.cjs`。服务只使用 Node 内置模块，不需要 npm install，不会自动安装软件。

第一次打开后，在设置中点击准备离线资源，等待提示全部就绪。页面、知识数据和中英文 OCR 资源会保存在当前浏览器的此站点缓存中。缓存完成后，可以关闭网络继续使用；同一地址也可在本地服务停止时重新打开。浏览器清理站点数据、隐私模式、存储空间不足、操作系统回收缓存均可能导致缓存丢失。请定期导出 JSON 备份；缓存不是数据备份。

服务默认仅允许本机连接。需要手机在同一家庭网络访问时，使用 `node server.cjs --lan`，浏览器打开窗口打印的局域网地址。手机和电脑的数据彼此独立，无账户同步，可通过导出/导入备份转移。

**普通局域网 HTTP 不满足 Service Worker 的安全来源要求，手机不能据此获得 PWA 离线重开能力。** 手机离线需要受信任的 HTTPS 来源，并在该设备上完成离线资源缓存。iOS 的添加主屏幕入口、图标支持与系统存储策略可能不同；本交付未在实体手机上验证安装。PC 的 `localhost` / `127.0.0.1` 属于浏览器认可的本地安全来源。直接双击 HTML 使用 `file://` 不适合此版本。

## 本地 OCR

离线模式只加载同目录 `vendor` 资源，在本机 Web Worker 内处理图片。`workerPath`、`corePath` 和 `langPath` 均明确设为本地路径，没有 CDN 回退，也不会在失败时自动上传图片。可以在服务运行、电脑未联网时首次识别；断开服务后重开则需提前缓存。

打包版本为 Tesseract.js 5.1.1、tesseract.js-core 5.1.1，以及 `@tesseract.js-data/chi_sim` 和 `@tesseract.js-data/eng` 1.0.0 的 `4.0.0_best_int` 语言数据。包含四类核心的 JS/WASM 资源，以适配 SIMD 与非 SIMD 环境。运行资源共 12 个文件、34,842,409 字节（约 33.23 MiB），另有少量许可与清单文件。依赖源地址、文件字节数、SHA-256 校验值见 `vendor/dependencies.json`；许可信息见 `vendor/licenses`。

支持 JPEG、PNG、WebP，单张不超过 20 MB、4000 万像素；内部压缩到最长边不超过 2400 像素，并重绘为 JPEG。请一次上传一页或一题，保持正向、清晰与均匀光照。HEIC、PDF 和 SVG 需先转换或截图。

Tesseract 主要识别印刷文字，对手写、根号、分数线、几何图和复杂公式不可靠。OCR 输出只是录入草稿，必须对照原图校正题干、学生作答和分数；服务层不自动判题。识别不清时可手动录入。较旧手机可能识别较慢或内存不足。

## 联网 AI

仅在选择联网模式并发起相应操作时，向填写的端点请求。配置示例形式为 `https://服务域名/v1` 或完整 `https://服务域名/v1/chat/completions`，前者自动补上 `/chat/completions`。模型名称须按服务商填写。接受 HTTPS 端点，本机测试服务可使用 localhost/127.0.0.1 的 HTTP。

接口使用 OpenAI 兼容 Chat Completions：`Authorization: Bearer …`、`messages`，图片使用 `image_url` 数据 URL。照片提取需模型支持图片；文字诊断及复测题生成使用 UI 提供的提示词。部分供应商只支持 Responses 或其他私有协议，不能直接接入。服务商必须允许浏览器 CORS 请求，包括当前页面来源、Content-Type 和 Authorization 请求头；本地静态服务不提供 API 代理。

密钥只由调用者传入请求头，服务层不保存到 LocalStorage、日志、URL 或缓存。Service Worker 只处理本应用白名单静态 GET，不缓存 AI API、跨域请求或带 Authorization 的请求。请求使用 `cache: no-store`，不跟随重定向。远程返回的原始错误正文不展示，以免服务端回显敏感信息。AI 请求超时为 180 秒，失败后可显式切换离线继续。

联网 OCR 会将所选图片发送给用户指定的服务商；诊断和出题会发送对应提示词中的信息。避免上传姓名、学校等无关个人信息。返回内容应人工检查，不作为能力测量的已验证结论。

## 验证边界与维护

服务层已做模拟请求验证：端点拼接、文字/图片请求格式、非法端点拒绝、不缓存请求与图片类型限制；静态服务已做实际 HTTP 验证：目录穿越拒绝、文件白名单、GET/HEAD 和 MIME。没有使用真实供应商凭据，**没有完成远程 API 联调**。浏览器 OCR、断网重开与手机布局的实际测试结果见最终验收记录，不以代码检查代替实测。

更新页面时需同时更新 `services.js` 与 `sw.js` 中的 VERSION，并确保两处资源清单一致，重新点击准备离线资源。服务启动后页面采用网络优先策略，断网时读取缓存；固定版本 vendor 采用缓存优先。不要删除语言包或核心文件，也不要把不同版本依赖混装。
